# 预注册：v5（验证器的现实性，离线，不调用 LLM）

写于 2026-10-21，尚未运行。

## 问题

前几轮使用的验证器就是合成任务的真值函数（validation split）。真实科研中没有这样的真值；而且一次真值评估通常比一次代理评分贵得多。本轮要回答：

1. 验证器有噪声、有偏差，或者干脆只是一个代理指标时，验证门槛还能不能挡住有害修改？还能不能带来收益？
2. 验证评估更贵（10 倍成本）时，收益还剩多少？

## 设计（全部离线：mock Planner/Analyzer，真实 GA、Controller、门槛，进程内 scorer）

### 验证器（都不读取候选的分数，只从候选表示重新计算）

| 版本 | 定义 |
|---|---|
| `oracle` | 现有真值验证器，作为对照 |
| `noisy` | 真值加上每个候选独立的高斯噪声（σ = 0.1，每次调用重新抽样，种子固定） |
| `biased` | 真值模型的中心向一个固定的随机单位方向偏移 0.1，模拟有系统偏差的低精度模拟器 |
| `proxy` | 任务的初始目标 scorer 本身（`minimize` 时取负值）。对有 bug 的任务，它就是那个有 bug 的 scorer；对优化器配置任务，它与真值方向一致但没有噪声 |

### 验证成本

每次验证中，每个候选的评估计费 1 倍或 10 倍，计入同一个评估预算（上限 5000）。

### 组别

| 组 | 判断器 |
|---|---|
| A | 无 Controller（原版） |
| SIM | 模拟判断器（明确标注为模拟，不是 LLM）。每次调用时：<br>• 如果正确修复尚未被接受：60% 概率提出正确修复；否则在错误或利用 bug 的修改中均匀选一个<br>• 正确修复已被接受后：50% 不做修改，50% 选一个错误修改 |
| RND | RandomTargetJudge（随机目标对照） |

SIM 和 RND 都与 4 种验证器 × 2 种成本交叉组合。所有组都使用 v4 的分阶段门槛：最多 3 个阶段，延长条件为 0 < Δ < 0.02，接受时沿用试验种群。

### 修改集合

沿用 v4 校准中的探测修改（1 个正确修复 + 2 个错误修改，真实效果分类沿用 v4 校准结果）。另外为 3 个有 bug 的任务各加 1 个"利用 bug"的修改（真实效果在本轮重新测定）：

| 任务 | 利用 bug 的修改 |
|---|---|
| overflow_scorer | 提高"最大化 parameter_mean"的权重到 5 |
| underflow_cost | 加入"最小化 parameter_mean"，权重 5 |
| offset_scorer | 提高"最大化 parameter_mean"的权重到 5 |

如果该目标已经存在，就改为 `set_weight`。

### 其他设置

- **任务**：stagnant_search、noisy_search、frozen_mutation、overflow_scorer、underflow_cost、offset_scorer。
- **目标条件**：`initial` 与 `planner_observed`（同 v4）。
- **种子**：0–4。
- **预算**：与 v4 相同；以预算为停止条件；GA 设置为 32×10，加上任务预设的覆盖项。

## 指标

- **最终测试指标**：始终用真值的 test split 计算，与验证器无关；报告平均值和成功率（阈值同前）。
- **SIM 组中被接受修改的真实类别**：有益、中性或有害，尤其关注**有害修改的采纳次数**。
- **验证支出占评估预算的比例**、完成的主循环轮数。

## 预期（运行前写下，用来事后对照）

- **noisy / biased**：有害修改的采纳率可能略升，收益下降，但仍应优于 A。
- **proxy**：在有 bug 的任务上会拒绝正确修复、接受利用 bug 的修改，相当于 Goodhart 失效；在优化器配置任务上与 oracle 接近。
- **10 倍成本**：可尝试的干预次数大幅减少，收益明显下降，甚至可能低于 A。

## 局限

- 判断器是模拟的。真实 LLM 判断器的提议分布与此不同，并且依赖提示词。
- Planner 是 mock，目标固定不变。
- 结果只说明"在这些假设下"框架的稳健性，不能替代真实任务上的检验。
