# 预注册：v4（改进验证门槛：分阶段验证 + 沿用试验种群）

写于 2026-10-20。v4 的离线校准和真实运行都还没开始。

## 动机

在 v3 的 offset_scorer 上，同一个正确修复（输出清洗）被提出了 14 次，其中 12 次被旧门槛拒绝。旧门槛只看"下一轮"的提升，而这次一轮内的提升只有 0.000–0.010。这类修复要过几轮才见效，所以旧门槛会误拒正确的修改。

## 新门槛规则（固定，`validation.mode: sequential`）

- **第 1 阶段**与旧门槛完全相同：候选与基线各跑一个完整的"下一轮"，使用相同的 2 个种子，独立验证器在 validation split 上打分。
- 设 Δ = 候选均值 − 基线均值，在每个阶段结束时判断：
  - 若 Δ ≥ 0.02（且 Δ > 0）：**接受**，停止测试；
  - 若 Δ ≤ −0.02：**明显变差，拒绝**，停止测试；
  - 其余情况：结果不明确，两侧各自从自己的试验种群继续跑一轮，种子不变。最多 3 个阶段，第 3 阶段仍不明确则**拒绝**。
- 每次延长之前检查预算；预算不够时拒绝，原因记为 `budget_insufficient_for_extended_validation`。所有阶段的成本都计入预算。
- 接受时，把候选试验中验证分最高的那个种群作为主流程下一轮的起点，这样试验算力不会白费。拒绝时不沿用，状态完全回滚。
- 旧门槛（`mode: single`）仍然是默认设置，与 v1–v3 的行为逐字节一致。

## 研究 1：离线门槛校准（不调用 LLM）

- **任务**：stagnant_search、noisy_search、frozen_mutation、overflow_scorer、underflow_cost、offset_scorer。
- **修改**：每个任务 3 个，都是单操作：1 个正确修复，加 2 个看似合理的错误修改。完整列表见 `gate_calibration.py`。
- **真实效果的测定**：
  - Planner 和 Analyzer 用 mock，目标固定为任务的初始目标；GA 配置与真实运行相同（32×10，加上任务预设的覆盖项）。
  - 第 1 轮之后强制应用该修改，再跑到第 8 轮；对照组不做修改。
  - 用 5 个种子分别计算 test split 上的差值，再取平均。
  - 均值 > +0.05 记为**有益**，< −0.05 记为**有害**，其余为**中性**。
- **门槛判定**：同样的 5 个种子，在第 1 轮之后由脚本提出该修改，分别用旧门槛和新门槛做一次判定。
- **报告内容**：
  - 有益修改的接受率（越高越好）；
  - 有害修改的接受率，即**误采纳率**（应保持为 0 或接近 0）；
  - 中性修改的接受率；
  - 每次判定的平均评估成本。
- **注意**：规则的提出参考了 v3 offset_scorer 的失败，校准任务也包含这些已见过的任务。规则参数（3 个阶段、±0.02）在此固定，不根据校准结果调整。

## 研究 2：真实 LLM 端到端

- **组别**：B、C、D，提示词设置与 v3 相同，唯一的改变是验证门槛换成新门槛。
- **任务与种子**：frozen_mutation、offset_scorer，种子 0、1、2，与 v3 相同，可以逐格配对比较。
- **其他**：预算、模型与 v3 相同。A 组不受门槛影响，直接复用 v3 的结果。
- **主要指标**：
  - 与 v3 旧门槛相比，成功数和测试指标的配对差；
  - 正确修复的被拒次数；
  - 被接受修改中属于最佳目标的比例；
  - 成本。
- 不做显著性检验。研究 2 中的任务对门槛来说属于"已见过的"任务，因此一般性的证据以研究 1 为主。
