# v4 结果：改进验证门槛（分阶段验证 + 沿用试验种群）

- **预注册**：`../../PREREG_v4.md`，含 3 次运行中修订，修订原因都写在文中。
- **代码**：f190ba2。**配置**：`ab_v4_config.yaml`。
- **新门槛规则**：
  - 提升 Δ ≥ 0.02：接受；
  - 0 < Δ < 0.02：继续下一阶段，最多 3 个阶段；
  - Δ ≤ 0：拒绝；
  - 接受时沿用候选试验中最好的种群。

## 研究 1：离线门槛校准（不调用 LLM；结果可复现，两次重跑完全一致）

- 设置：6 个任务 × 每任务 3 个探测修改 × 5 个种子，两种目标条件。
- 每个修改的"有益 / 有害"由强制应用后长期运行（8 轮）的效果决定。

| | 旧门槛 | 新门槛 |
|---|---|---|
| 有益修改被接受（预注册校准，80 次判定） | 66/80 | **71/80** |
| v3 真实误拒情形：用当时 Planner 的目标集，修复的长期效果为 +0.69 ~ +0.93（40 次判定） | 3/40 | **40/40** |
| 有害修改被接受（预注册校准 + 健康设置补充检查） | 0/5，2/40 | 0/5，2/40（未增加） |
| 中性修改被接受 | 3/75 | 7/75 |
| 每次判定的评估数 | 1302 | 1891（×1.45） |

**结论**：在固定的目标集合下，新门槛基本消除了"见效慢的正确修复被误拒"，同时没有增加有害修改的误采纳。代价是验证成本更高，并且会多接受一些中性修改。

需要说明的是，研究 1 中 Planner 和 Analyzer 用的是 mock，目标在整个运行中固定不变；而真实运行中，目标会随 LLM Planner 的规划在每轮变化。

**解读：**

1. **新门槛确实修复了误拒。** 在研究 2 的 LLM 组中，正确修复被拒绝的次数从 4 次降到 0 次。B 组在 offset_scorer 上从 0/3 成功变成 2/3。
2. **但新门槛暴露了一个规则漏洞：没有噪声下限。** 当两侧真实质量都接近 0 时，Δ 往往是一个极小的正数（四舍五入后显示为 0.000），却被当作"正向趋势"一直延长到 3 个阶段。例如 D 在 frozen s1 和 offset s1 上的权重微调，一次就耗掉 3864 次评估（约为预算的 77%），整次运行只剩 4 轮。这是 D 的平均测试指标下降（0.574 → 0.361）的主要原因。
3. **LLM 本身的随机性很大。** 同一个种子、同样的提示词，Judge 前后两次给出的提议不同，例如 B 在 frozen s1 上，v3 第一次就提出了正确修复，v4 没有。所以每组 6 格的差值中，有相当一部分来自 Judge 的随机性，而不是门槛本身。
4. **汇总 LLM 组（B + D，各 12 格）**：成功数从 3/12 增加到 4/12；平均测试指标从 0.385 升到 0.481。这是方向偏正的弱信号，但没有达到可以下结论的程度。

## 运行中发现并修复的问题（都已写入预注册修订）

- **修订 2**：原规则 `reject_margin = −0.02` 会把恰好为 0 的提升也当作"不明确"并延长测试，已改为 0.0。研究 2 因此从头重跑。
- **修订 3**："沿用试验种群"之后，知识库中上一轮种群的统计缓存没有清除，导致 Analyzer 在 argmax 时遇到空序列而崩溃。已修复，并加了回归测试（已确认修复前会失败）。offset_scorer 的 9 格全部重跑。
- 另有 1 次原版 SAGA Planner 连续提出不存在的目标而失败，与 Controller 无关，随 offset_scorer 一起重跑。

## 下一步建议（未执行）

1. **给"继续测"加一个噪声下限**，例如 Δ > 0.005，或按两个验证种子之间的差异来设定。离线就可以校准，例如拿中性修改作为参照。
2. **给单次运行的验证支出设上限**，例如不超过总预算的 40%，防止一次验证就把搜索预算吃光。
3. **降低延长阶段的成本**：例如延长阶段只用 1 个种子，或者缩短试验代数。
4. **增加真实运行的种子数**，以便把门槛效果和 Judge 的随机性分开。
